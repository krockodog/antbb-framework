# Interface languages

The running UI is German by default and can be switched to English. German is the source wording. English is a full second catalog, not a shorter summary.

## Resolution order

1. `?lang=de` or `?lang=en` on the current URL.
2. The `antbb_lang` cookie (SameSite=Lax, one year, not HttpOnly, so the static hub can read it).
3. The first supported tag in `Accept-Language`.
4. German.

An unknown tag such as `zz` is ignored. The next source is used, and if none match, the language is German.

Setting `?lang=` also writes the cookie, so the next page keeps the choice. The switcher keeps the current path and the rest of the query string and only replaces `lang`.

## One catalog

`antbb/locale/de.json` and `antbb/locale/en.json` hold the same keys. `antbb/i18n.py` loads them. Templates call `{{ t('key') }}`. The base template injects `window.I18N` for page scripts, which call `window.t('key')`. The Next.js hub imports the same JSON files.

Do not translate identifiers, environment variables, file paths, commands, log lines, JSON keys, severity codes, or tool output. Translate the label a person reads.

## Add a string

1. Add the key to both JSON files. Empty values are not allowed.
2. Use `{{ t('the.key') }}` in a template, `window.t('the.key')` in page script, or `t('the.key')` from `useI18n()` in the hub.
3. Placeholders are `{name}` and are filled with `t('the.key', name=value)`.

Inside a Jinja `{% for %}` loop, do not call `t` if the loop variable is also named `t`. The converted pages bind `{% set tr = t %}` and call `tr`.

## Coverage

The catalogs cover the shell and the page body:

- Every template under `antbb/web/templates/` extends `base.html`, which carries the DE | EN switcher.
- Red, Blue, brain, target, WLAN, and the server WLAN page, including table headers, empty states, buttons, titles, placeholders, `aria-label`s, and `confirm` / `alert` text.
- The page scripts listed in `tests/test_i18n.py` (`red_cards.js`, `blue*.js`, `wlan*.js`, `orchestrate.js`, `soldiers.js`, `rating.js`, `hub-real.js`, `attackpath.js`, `antmap.js`, and `brain/*.js` that draw labels).
- User-facing HTTP errors, the WLAN notice, Blue phase notes, queen live lines, and the OAuth / provider pages. JSON field names stay the same; only the text value follows the request language.
- The Next.js hub uses the same JSON for headings, queen cards, the colony room, and the yellow run list.

## Deliberately untranslated

- Identifiers, environment variables, paths, commands, JSON keys, severity and status codes, and tool output.
- Skill and reference markdown, registry task text, and generated report bodies. Those are stored evidence, not chrome. The report form labels are translated; the stored chain text is not rewritten.
- Log lines, including `console.info` in `antmap_colony.js`.
- Vault status tokens such as `VERIFIZIERT` that the UI compares with file contents.
- The legacy button matcher in `hub-real.js`, which looks for the old German label so it can replace it.
- Static Next.js `<title>` tags are bilingual (`Red Queen · Rote Königin`) because the export has no request to resolve a language. The visible headings use the catalog.

`antbb/locale/allowlist.txt` records the source lines that must keep German for those reasons. `tests/test_i18n.py` checks key parity, non-empty values, fallback to German, the switcher on every template, and that converted templates and scripts have no other hardcoded German sentences.
